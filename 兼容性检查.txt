Orca Plate Queue 0.7.5 兼容性检查
构建：20261102.1；连接组件：0.7.3（DLL 与已发布组件完全一致）

已修复
- Windows ctypes 在 handle 已指定时仍检查 name；None 导致 TypeError。
- 改用空字符串与已有非空模块句柄；不调用 LoadLibrary 加载新的联网库。
- 绑定失败显示独立错误类型；不再当成设备 JSON 无效，也不再只显示等待状态。
- 页面、服务、发布版本与构建号一致，并检查实际 wheel 中的版本信息。

本地验证（2026-11-02）
- OrcaSlicer 自带 Python 3.12.13：280 项测试通过。
- Python 3.13.1：280 项测试通过。
- 实际发布包、运行边界与离线发布验证：24 项测试通过。
- 页面工作流：69 项测试通过，桌面与窄窗口无横向溢出。

- 中文、空格、Unicode 文件名：私有缓存、SQLite 保存与重开、执行器独占锁通过。
- 快照边界、UTF-8、重复实例、旧组件拒绝发送、AMS 稀疏编号及外挂映射沿用现有回归测试。
- 新增 GitHub Windows Python 3.12 / 3.13 自动测试；远端结果需在 Actions 查看。

验证边界
- 本地宿主为 Windows 11（10.0.26200），不是 Windows 10 实机。
- 已核对当前 Python/原生桥接使用的 Windows 接口；没有引入 Windows 11 专用接口。
- 连接组件未修改；原生 ABI 与独立安装器测试记录复用该固定组件此前的隔离验证。
- 未向真实打印机发送、停止、跳过任务，也未进行实机自动换盘或 Windows 10 整体验收。
- 底层 SDK 的文件路径需要能够用系统代码页表示。若存储路径含无法表示的字符，会返回明确的路径编码错误（-7）；不会换成外挂或继续发送。

用户更新
更新到队列 0.7.5，保存工程，完整退出 Orca 后重新打开。
已有匹配的 0.7.3 连接组件无需重新安装；初次使用仍须安装独立连接组件并启用联网、登录 Bambu Cloud。
如果仍无设备，先看连接说明中的具体错误，而不是反复重装打印机或修改 AMS。
