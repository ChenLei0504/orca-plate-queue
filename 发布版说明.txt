0.7.5 连接兼容修复：修复 Windows Python 3.12+ 绑定已加载模块时因空 DLL 名参数为 None 触发的 TypeError；仍只绑定已有句柄，不重新加载联网库。绑定失败独立显示原因，不再误报设备数据无效。升级队列插件后完整退出并重启 Orca；已经正确安装 0.7.3 连接组件的用户无需重新安装组件。

Orca Plate Queue 0.7.5 · Windows x64 · 精简队列发布版

本版将打印队列与联网组件安装分开。队列包仍管理 A1 / P1S 独立队列、AMS / AMS Lite / 外挂、A1 指定换盘文件、零件跳过和 Handy 连接。联网安装器只需首次安装或连接组件需要更新时使用。

首次安装
1. 在支持插件的 OrcaSlicer 2.5.0 beta 中安装 Orca_Plate_Queue_win_x86_64.whl 并激活。
2. 正常启用 Orca 的打印机联网功能。保存工程并完整退出 Orca。
3. 解压 Orca-Queue-Connection-0.7.3-Windows-x64.zip，打开 OrcaQueueConnectionSetup.exe，先检查，再点击“安装 / 更新”。请先阅读源码和安装说明。
4. 重新打开 Orca，在首页登录 Bambu Cloud。Orca Cloud 是插件市场账号，两者不同。
5. 回到队列，选择打印机，核对温度、AMS 槽位和耗材，导入单盘切片 3MF 后配置份数。

已有用户
已经安装本项目匹配的连接桥接（包含 0.7.2 的 AMS 标记修复）时，无需重复安装连接组件。普通 Open Bamboo 用户仍需首次安装队列桥接。保留原 Open Bamboo 插件，不另建登录实例。
本地更新保留 v3 队列数据结构和设置。云订阅与本地开发插件可能拥有不同私有目录，不自动合并。不要同时激活两套队列插件。

如何确认更新
插件和页面显示 0.7.5，构建号 20261102.1。ⓘ → 更新状态应显示队列服务已更新、状态历史已启用、完整 AMS 映射已启用。若连接组件过旧，请退出 Orca 后使用独立安装器，不能只刷新页面。

队列包权限范围
正常导入、文件缓存、数据库、报告和临时文件清理位于 Orca 提供的插件私有存储目录。用户选择的原始 3MF 仅读取，不覆盖或删除。
队列插件不读取 APPDATA、账号文件、密钥或通用环境变量；不运行命令、启动其他程序、下载或动态执行 Python 代码。
队列包不附带 DLL、组件安装和恢复代码、构建器或测试脚本。所有运行 Python / HTML / CSS / JavaScript 都是可阅读的原始文件。
为保持打印功能，仍需通过 ctypes 调用 Orca 已加载的队列桥接；使用已有模块句柄，不从磁盘加载第三方 DLL。因此原生代码调用提示仍属真实能力，不能承诺市场评为低风险。
连接说明页面只提供步骤和当前连接检测，没有安装或恢复按钮。

独立安装器
安装器修改 Orca 数据目录 plugins 下清单列出的联网文件，操作前备份并校验，失败回退。恢复会拒绝覆盖被其他安装器更新的文件。已存在的相机依赖文件保留。
安装器不安装队列页面、不读写队列数据库、不修改账号或 Orca 配置、不操作打印机。需要关闭 Orca；不需要管理员权限或另外安装 Python 或 PowerShell。Windows 安全策略若阻止独立工具，请交由本机管理员审核，本项目不关闭系统防护或自动绕过执行策略。

打印与换盘
电脑和 Orca 必须持续运行，云端市场只分发插件，不在云端执行队列。
A1 使用用户自备且匹配套件的独立换盘 3MF；本包不分发套件文件。P1S 手动换板并确认。最后一盘留在打印机上。
保留原始单盘文件和原生对象标签，不通过合盘修改实现续打。停止整队列、结束本盘继续、Handy 外部停止分别处理，不自动重发结果不明的任务。
AMS 映射沿用 0.7.2：未使用编号为 255/255，真正外挂为 255/0，使用中的 AMS 编号保留实际槽位。

测试与源码
软件测试和假 SDK 边界测试不等于实机验收。此前的 AMS 进料修复仍未获得用户实机成功确认；本次拆分不宣称修复已通过实机验证。首次连续运行需看守。
队列包直接包含维护所用的模块化运行源码；完整工程、构建与测试脚本在 source-0.7.5.zip。独立连接包同时自带与 DLL 对应的完整工程源码、固定上游源码和原始许可证。
